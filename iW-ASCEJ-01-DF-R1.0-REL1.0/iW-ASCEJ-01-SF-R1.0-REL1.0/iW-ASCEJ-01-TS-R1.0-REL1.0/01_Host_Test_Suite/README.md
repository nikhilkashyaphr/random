# Host-side tests

Run everything with `./run_all.sh`. You need gcc, cmake and Qt5 development
files, the same as for the GUI build. No board, root access or GPU is
required.

| Suite | What it proves |
|---|---|
| `firmware/run_tests.sh` | The DAC input routing code in `main.c`, taken **verbatim**, drives a register-level model of `DDS_H2C_switch` wired as the bitstream wires it (S00 host, S01 DDS). Covers boot default, both selections, readback, invalid input and a single commit per change. |
| `pcie_emu/` | The GUI's real `RfdcControl` talks to the firmware's real `pcie_cfg.c` through a file standing in for BAR2. Covers the full sync, readback of every register, and DAC source changes with confirmation, defaults and rejection. After every command it checks what the DAC would actually play. It is built twice: against 1.2.1 firmware, and against **1.2.0** firmware (`legacy_1.2.0/`) to prove the GUI routes correctly on a board that has not been reflashed. |
| `gui/tx_path_test` | IQ generator → real FIFO → a consumer that replays chunks the way `iwfg_h2c` does → spectrum. Covers DAC packing, the frequency actually transmitted, SFDR through the replay (coherent against the old behaviour), live updates, stop/restart and FIFO-error recovery. |
| `gui/sim_loopback_test` | The simulator's RF loopback: DDS tone, generator waveform (sine, square, negative frequency), host with nothing transmitting, out-of-band tones, and the modem demo left unchanged. |
| `gui/control_window_test` | The H2C / RFDC window driven offscreen as a user would, in simulation and in live mode without a device. Covers the H2C buffer following the backend and the link monitor. It also runs the loopback check against a stand-in receiver: the receiver follows (verified), stays on the DDS (not verified, cause named), or reads at a wrong display rate (reported as scaling). |
| `gui/app_loopback_test` | The **whole application** in Simulation. It runs the real MainWindow, DSP chain and simulated RF loopback, driven through the H2C window: generator → "DAC" → "ADC" → spectrum → **Verify loopback**. Host passes; DDS fails with the cause. |
| `h2c_emu/h2c_emu_test` | The **real** `iwfg_h2c` (built from `backend/H2C`) fed by the real IQ generator, with the card replaced by an `LD_PRELOAD` fake (`fake_iwfg.so`) that records what the DAC would play and consumes it at the DAC's 763 MiB/s behind a per-transfer cost. It shows that 16 KiB chunks starve the DAC (the bench symptom) while 1 MiB (the default) and 16 MiB keep it fed. It also checks that the DAC stream is seamless across loop boundaries (SFDR above 80 dB), that the loop is written once (`GR_updates=0/s`), that live changes arrive, that Stop leaves silence, and that a refused buffer triggers the step-down. |
| `h2c_emu/loopback_emu_test` | The whole **send-and-receive chain**: real `BackendLauncher`, real `iwfg_h2c` and `c2h_stream`, real generator and `DmaSource`. The fake card loops what the "DAC" plays back into the "ADC". Faults are injected as the bench saw them: a C2H driver error (restart, re-attach, transmit untouched); a stall that a same-size reopen cures (no step-down); a card refusing large transfers (reopen, then step-down); a card that never consumes (bottom rung, capture unaffected) or consumes late (back to 1 MiB); a card that stops delivering C2H (`resetDevice()` brings it back); helpers ignoring SIGINT/SIGTERM (`stop()` never blocks); Start during Stop; a missing H2C node; a capture-only session. It also checks that stop closes `/dev/iwfg1` before `/dev/iwfg0`, that the capture FIFO pipe is enlarged, that the helper pre-flight touches no device, that the reader does not spin without a writer, and the transmit-guard arithmetic. |
| `h2c_emu/app_live_emu_test` | The **whole application** in a live PCIe session with the emulated card. The test presses Start generator and Verify loopback, then Stop and Start. It then lets the capture helper be killed by an injected driver error, and then makes the card stop delivering C2H data. It checks that the loopback verifies after each, that no dialog appears for a recovered helper or a reset device, that `sdr_backend.log` records the reasons, and that the GUI thread never pauses for more than a second (a 20 ms heartbeat runs throughout). |
